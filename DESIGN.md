# DESIGN.md — Country Search

## 1. Механизм отмены устаревших запросов

В приложении используется реальная отмена сетевых запросов через `AbortController`, а не фильтрация результатов по флагу или таймстампу.

### Как это работает

1. При каждом изменении ввода в `createSearchController` (`src/search/searchController.ts`) мгновенно вызывается `abortCurrentRequest()`, который вызывает `AbortController.abort()` для текущего активного запроса — **до** истечения задержки `debounce`.
2. В `searchCountries` (`src/api/countries.ts`) внешний `signal` объединяется с таймером ожидания ответа через `AbortSignal.any([signal, AbortSignal.timeout(timeoutMs)])`.
3. В блоке `catch` контроллер передаёт ошибку в чистую функцию `classifyError` (`src/search/classifyError.ts`), которая чётко разделяет:
   - `AbortError` — штатная отмена пользователем, ошибка игнорируется и не выводится на экран;
   - `TimeoutError` — превышено время ожидания сервера, пользователю показывается ошибка с кнопкой «Повторить»;
   - `HttpError` (статусы 4xx/5xx, кроме 404) и сетевые ошибки (`TypeError`) — показываются пользователю с кнопкой «Повторить»;
   - HTTP `404` обрабатывается в `searchCountries` до проверки `!response.ok` и возвращается как пустой массив `[]` (состояние «ничего не найдено»).

### Почему не просто флаг «актуальный ли ответ»

Игнорирование ответа флагом постфактум маскирует проблему в UI, но **не отменяет сам сетевой запрос**: браузер продолжает держать соединение открытым, загружать тело ответа и парсить JSON, тратя трафик и ресурсы устройства. `AbortController` реально прерывает `fetch` (в DevTools Network такие запросы имеют статус `canceled`).

## 2. Обоснование задержки `debounce` (300 мс)

Выбрана задержка **`300 мс`** (`debounceMs = 300` в `src/search/searchController.ts`).

- **Если убрать задержку (`0 мс`):** запрос уходил бы на каждую нажатую клавишу (`s`, `sp`, `spa`, `spai`, `spain`), создавая лишнюю нагрузку на API, риск упереться в rate-limit и постоянное мерцание индикатора загрузки.
- **Если сильно увеличить (например, `1500 мс`):** приложение казалось бы неотзывчивым — после окончания ввода пользователю пришлось бы слишком долго ждать начала поиска.
- **`300 мс`** — комфортный баланс: интервал между нажатиями клавиш при обычном наборе обычно составляет 150–250 мс, поэтому промежуточные буквы отсекаются, а после паузы результат появляется практически сразу.

## 3. Оценка сложности (Big O)

- **`mapCountryResponse(raw)` (`src/api/mapper.ts`):**
  - Временная сложность: **$O(L + C + B)$**, где $L$ — количество языков (`languages.length`), $C$ — количество валют (`currencies.length`), $B$ — количество граничащих стран (`borders.length`). Для одной страны эти величины ограничены небольшими числами, но линейно зависят от размера вложенных массивов. Пространственная сложность: **$O(L + C + B)$** (создаётся новый объект и копии массивов без мутации исходных данных).
  - При маппинге массива из $N$ стран в `searchCountries`: **$O(N \cdot (L + C + B))$**.
- **Кэш и дедупликация (`src/api/cachedSearch.ts`):**
  - `cache` и `inFlight` реализованы на базе `Map<string, ...>`. Поиск и запись по нормализованной строке запроса длины $m$ выполняются за **$O(1)$** в среднем по количеству записей в кэше (и $O(m)$ на вычисление ключа `trim().toLowerCase()` и хеширование строки).
  - При одновременном запросе одного и того же ключа переиспользуется один `sharedPromise`, а обёртка `raceWithAbort` работает за **$O(1)$**.
- **История запросов (`src/search/searchHistory.ts`):**
  - Поскольку размер списка ограничен константой `maxItems = 8`, фильтрация дубликатов и сериализация в `localStorage` выполняются за **$O(H)$**, где $H \le 8$, то есть фактически за **$O(1)$**.

## 4. Принципы чистого кода и их применение

- **Разделение ответственности (Separation of Concerns):** вся бизнес-логика, работа с сетью, отмена, кэширование и стейт-менеджмент (`src/api/`, `src/search/`, `src/utils/`) полностью отделены от DOM и тестируются без браузера. Слой `src/ui/` отвечает только за отображение состояний и пользовательские события.
- **Принцип единственной ответственности (SRP):**
  - `debounce` (`src/utils/debounce.ts`) — только отложенный вызов;
  - `mapCountryResponse` (`src/api/mapper.ts`) — только преобразование контракта API;
  - `classifyError` (`src/search/classifyError.ts`) — только классификация ошибок;
  - `createCachedCountrySearch` (`src/api/cachedSearch.ts`) — только кэш и дедупликация;
  - `createElement` (`src/ui/dom.ts`) — только безопасное создание DOM-элементов.
- **Чистые функции и иммутабельность:** `mapCountryResponse` и `classifyError` не имеют побочных эффектов; `mapCountryResponse` копирует массивы (`[...(raw.borders ?? [])]`), не мутируя входные данные.
- **Безопасность и строгая типизация:** динамический DOM строится только через `document.createElement` и `textContent` (`src/ui/dom.ts`, `src/ui/countryView.ts`, `src/ui/app.ts`) без `innerHTML`, что исключает XSS. Состояния UI и ошибки описаны через discriminated unions (`SearchState`, `ClassifiedError`).
